# Rangoli Got Latent

A static browser game for a live, host-led Rangoli drawing and jury-rating event.

## Files

- `index.html` — the complete game (host, team drawer, and jury views).
- `vendor/mqtt.min.js` — MQTT client library used for live communication.

## Deploy with GitHub Pages

1. Upload the contents of this folder to the root of a GitHub repository.
2. Keep the `vendor` folder beside `index.html`; the game loads `vendor/mqtt.min.js`.
3. In the repository, open **Settings → Pages**.
4. Under **Build and deployment**, select **Deploy from a branch**, choose `main` and `/ (root)`, then save.
5. Open the published Pages URL.

No build step or server-side application is required.

## How to use

- Host: open `?role=host`.
- Team: open the team invite link generated by the host.
- Jury: open the jury invite link generated by the host.
- Same-browser test mode: add `&local=1` to each role URL. This is only for testing tabs in the same browser profile; it does not connect separate devices.

The host creates a room and generates the team and jury invite links. Keep the host page open throughout the game. If you start a brand-new game, the room code changes and old invite links stop being valid.

## Live communication and limitations

The app relays real-time messages through public MQTT brokers over secure WebSockets. It does not use a private database or a dedicated backend. The host page holds the live game state in that browser's local storage, so keep that browser and tab available during the event.

Public brokers are shared infrastructure and are not a private or production-secure messaging service. Treat room links as event links, share them only with participants, and test the full flow across the actual devices and networks before the event. Broker availability can vary; the client includes broker retry/failover behavior.

## Game rules implemented

- The host selects or uploads a Rangoli reference image.
- The team locks its predicted score before drawing.
- The artist gets two minutes to recreate the reference.
- Five jurors must join before the host can open rating.
- Jurors submit whole-number ratings from 1 to 10.
- The host reveals the ratings and calculates the average.
- The team's prediction is accepted in 0.1-point increments so it can match the average of five whole-number ratings exactly.
- A team wins only when its prediction exactly equals the jury average.

## Pre-event test checklist

- Test host, team, and all five jury links on separate devices.
- Test across the Wi-Fi/mobile networks participants will use.
- Confirm the team can join without manually refreshing.
- Confirm drawing strokes sync to the host while the artist draws.
- Confirm all five jury members can submit and have their ratings revealed.
- Confirm a prediction such as `6.4` can match a five-juror average of `6.4`.
- Keep the host tab open and plugged into power for the event.
